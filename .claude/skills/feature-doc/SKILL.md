# /feature-doc 功能说明书生成技能

## 功能概述

此技能用于在功能实现完成后，自动生成完整的设计说明书文档。说明书包含以下章节：

1. **功能概述** - 简述功能目的和用户价值
2. **核心特性** - 列出所有实现的功能点
3. **技术实现** - 详解技术方案、文件结构、数据流
4. **API 文档** - 后端接口规范（如有）
5. **使用指南** - 用户如何使用此功能
6. **故障排除** - 常见问题和解决方案
7. **性能考虑** - 性能指标、优化建议
8. **测试清单** - 功能验证检查项
9. **开发扩展** - 如何在此基础上继续开发

## 触发场景

用户在完成一个功能开发后，运行：

```bash
/feature-doc <功能名称>
```

例如：
```bash
/feature-doc 流程自动保存
/feature-doc 步骤预览功能
/feature-doc 移动端响应式设计
```

## 执行流程

### 第一步：分析最近变更

1. 获取最近的 git 提交（通常是功能实现的最后一个提交）
2. 分析 `git diff` 查看修改了哪些文件
3. 确定功能涉及的模块、页面、组件
4. 识别后端 API 变更

### 第二步：抽取技术细节

从代码中抽取以下信息：

**前端信息**：
- 修改的 `.vue` 组件文件
- 新增/修改的数据属性（data）
- 新增/修改的计算属性（computed）
- 新增/修改的方法（methods）
- 新增的生命周期钩子
- 关键 CSS 类名和样式特性

**后端信息**：
- 新增/修改的 API 路由
- 请求/响应格式
- 数据库操作（INSERT/UPDATE/DELETE）
- 错误处理逻辑

**其他**：
- 配置文件变更
- 依赖安装
- 环保变量需求

### 第四步：保存文档

文档保存位置规则：

1. **功能模块相关**：保存在模块目录下
   - 流程相关 → `docs/workflow/` 或 项目根目录

2. **文件命名规则**：
   ```
   <功能名称>_<类型>.md

   例如：
   - AUTO_SAVE_GUIDE.md - 自动保存功能
   - DUPLICATE_ENTRY_FIX.md - 故障修复
   - WORKFLOW_DESIGN_GUIDE.md - 系统设计
   ```

3. **多文档关联**：
   - 设计文档 (DESIGN)
   - 故障排除 (TROUBLESHOOTING)
   - 快速参考 (QUICK_FIX)
   - 用户指南 (USER_GUIDE)

## 文档质量标准

### ✅ 必须包含

1. **明确的目标** - 功能解决的问题
2. **完整的示例** - 代码片段、配置样本
3. **实际的截图/图表** - 视觉化说明（如可用）
4. **故障排除** - 常见问题和解决方案
5. **测试验证** - 如何验证功能正确
6. **相关链接** - 指向其他相关文档

### ✅ 推荐内容

1. **版本历史** - 功能迭代记录
2. **性能指标** - 量化的性能数据
3. **安全考虑** - 如有涉及
4. **可访问性** - 无障碍支持说明
5. **国际化** - 多语言支持说明

### ❌ 避免内容

1. 过于技术细节（应在代码注释中）
2. 个人观点（保持客观）
3. 重复的内容（避免冗余）
4. 过时的信息（定期维护）

## 常见问题

### Q: 说明书应该有多长？

A: 根据功能复杂度：
- 简单功能：200-300 行
- 中等功能：500-800 行
- 复杂功能：1000+ 行

### Q: 是否需要同时生成多个文档？

A: 建议为复杂功能生成多个文档：
- `FEATURE_NAME_DESIGN_GUIDE.md` - 设计文档（开发者）
- `FEATURE_NAME_USER_GUIDE.md` - 用户指南（用户）
- `FEATURE_NAME_TROUBLESHOOTING.md` - 故障排除（支持团队）
- `FEATURE_NAME_QUICK_FIX.md` - 快速参考（所有人）

### Q: 说明书应该版本控制吗？

A: 是的，建议：
1. 提交到 git（与代码一起维护）
2. 在文档中标注版本号
3. 记录版本历史变更
